# Итерация 2 — логика стола без GUI

**Статус:** готово, проверено юнит-тестами и сквозным сценарием на dev-сервере
(`/libresearch selftest` — 19/19).

## Цель

Оживить стол: слоты, бумага и заряды чернильницы, теория (вдохновение, прогресс,
блокировки), добор руки, розыгрыш карты с требованиями и эффектами, завершение
с переводом процентов в очки, награды и их забор. Без GUI — командами.

## Решения

1. **Запас знаний — attachment игрока** (`libresearch:knowledge`), а не поле стола:
   очки общие для всех столов, переживают смерть (`copyOnDeath`). Внутри —
   `Map<String, Long>` санти-очков, 100 = 1 очко.
2. **Награда — снимок в столе.** При завершении теории стол запоминает, сколько
   санти-очков он начислил по каждой дисциплине (`TheoryState.rewards`). Забрать
   можно `min(начислено, запас) / 100` целых очков: нельзя получить больше, чем дал
   этот стол, и больше, чем реально лежит в запасе. Остаток санти-очков остаётся и в
   запасе, и в снимке; он «докопится» следующей теорией на этом же столе.
3. **Старт блокируется, пока в снимке есть целое очко** (`hasPendingRewards`), а не
   пока есть любой остаток: 15 санти-очков после забора не мешают новой теории.
4. **`full_value_slots` инициализируется числом дисциплин стола** — штраф 2/3 в MVP
   выключен (решение заказчика №6). Карты `full_value_slots` просто увеличивают счётчик.
5. **Стартовое вдохновение — 5.** Формула `min(15, round(5 + 0.5·spiky + 0.1·hidden))`
   уже в ядре, но `spiky`/`hidden` пока 0: наблюдений и исследований-замков нет.
   Выбор бонусных блоков (и вычет за них) — итерация 4.
6. **Старт требует бумагу и чернила**, но ничего не тратит: как в оригинале, иначе
   можно начать теорию, которую невозможно играть.
7. **Добор:** 1 бумага, рука 2 карты (3, если есть жетон бонусного добора — жетон
   тратится). Переброс руки — просто ещё один добор за бумагу; отдельного реролла нет.
8. **Взвешенный выбор карт** через `core/WeightedPool`. Фильтры: `weight > 0`,
   не `bonus_only`, цена ≤ текущего вдохновения, дисциплина существует в этом типе
   стола и не заблокирована, выполнены `spawn.requirements`, нет дублей в руке.
   Бонусная колода — итерация 4.
9. **Все случайности фиксируются при доборе.** `DrawnCard` хранит id карты,
   выбранную дисциплину, цену, случайные числа и цели эффектов; сохраняется в NBT.
   Поэтому рука переживает перезаход и не «перебрасывает» значения между кадрами.
10. **Розыгрыш:** сначала проверяются чернила (1 заряд + `ink_charges`-эффекты) и
    бумага (`paper`-эффекты), потом требования; при нехватке карта не играется и
    ничего не списывается. Затем списываются требования, ресурсы, применяются эффекты,
    вычитается цена, рука очищается (невыбранные карты сгорают).
11. **При вдохновении 0** розыгрыш и добор запрещены, доступно только завершение.
    Отрицательная цена карты возвращает вдохновение с потолком на стартовом значении.
12. **Завершение** переводит проценты в санти-очки (`core/KnowledgeMath`), пишет их
    в запас игрока и в снимок наград, затем очищает теорию. Заблокированные
    дисциплины участвуют в конвертации.
13. **Чистое ядро.** `core/` не импортирует Minecraft; `WeightedPool.Rng` — свой
    интерфейс вместо `RandomSource`, адаптер — ссылка `ctx.random()::nextInt`.
    Побочный эффект: у тестов **нет Minecraft в classpath**, поэтому «затащить MC в
    ядро» невозможно даже случайно.
14. **JUnit 5** подключён только для тестов. В `build.gradle` добавлен
    `exclusiveContent` для групп `org.junit*`, `org.opentest4j`, `org.apiguardian`:
    иначе Gradle идёт за ними на недоступный `maven.neoforged.net` и ждёт таймаут.
    После первого скачивания `./gradlew --offline test` работает.

## Команды (итерация 2)

Все команды теории применяются к столу, на который смотрит игрок (до 8 блоков).
Отладочные — только для операторов (permission 2).

```
/libresearch theory start|draw|play <1..3>|finish|discard|status
/libresearch theory claim <discipline>|claimall
/libresearch theory set <discipline> <percent>      # только op
/libresearch theory inspiration <value>             # только op
/libresearch knowledge
/libresearch selftest                               # только op
```

`selftest` ставит временный стол, играет сценарий фейковым игроком и убирает за
собой: старт → добор → сброс → прогресс 115% → завершение → блокировка старта →
забор 2 медных слитков → остаток 15 санти → старт снова разрешён.

  с рассылкой клиенту.
- Точка входа: `LibResearch.java` — регистрация attachment.
- Тесты: `src/test/java/.../core/{KnowledgeMathTest,WeightedPoolTest}.java`.
- Сборка: `build.gradle` — JUnit, `test`, `exclusiveContent`, `useJUnitPlatform`.
- Заметки: `notes/03-mvp-design.md` §6 (уточнение про снимок наград).

## Как проверить

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
./gradlew --offline build        # включает test
./gradlew --offline test         # 11 тестов ядра

mkfifo /tmp/opencode/srv.in
( exec 3>/tmp/opencode/srv.in; while true; do sleep 5; done ) &
./gradlew --offline runServer < /tmp/opencode/srv.in
# после "Done (":
#   libresearch validate
#   libresearch selftest
#   stop
```

Ожидаемо: `SELFTEST: OK — пройдено 19 проверок`, в логе нет исключений.

## Известные проблемы

- Нет GUI: состояние теории пока не видно игроку, только через команды.
- Нет сканирования бонусных блоков и бонусной колоды (итерация 4): `bonus_only`-карты
  не выпадают, выбор бонусов не вычитает вдохновение.
- Нет блокировки стола за игроком: два игрока могут одновременно щёлкать команды
  одного стола. Для MVP не критично, в итерации 3 закроем открытым меню.
- `spawn.requirements` с `progress` проверяются по текущей теории; после `/reload`
  рука может содержать карту, которой больше нет — розыгрыш вернёт понятную ошибку.
- `selftest` использует FakePlayer и оставляет его запас знаний пустым; временный
  стол удаляется, предметы из его слотов пропадают (это тестовый блок).
- Формула вдохновения с `spiky`/`hidden` ещё не задействована: параметров нет в данных.

## Что осталось (за пределами итерации)

- GUI (итерация 3): фаза настройки бонусов, игровой экран, фаза наград, тултипы,
  причины отказа — на тех же методах `TheoryEngine`.
- Пакеты `network/` для действий GUI и синхронизация состояния.
- Бонусные блоки (итерация 4) и полный контент (итерация 5).
