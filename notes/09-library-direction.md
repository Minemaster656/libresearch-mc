# Направление проекта: библиотека, а не контент-мод

**Статус:** зафиксировано 01.11.2026 по итогам ручной игры. Заменяет часть решений из
`notes/03-mvp-design.md` и плана итераций в `AGENTS.md` (там же обновлённая таблица).

## 1. Позиционирование

Мод — **библиотека механики**, а не набор контента. Всё, что мы сейчас показываем в игре
(`libresearch:research_table`, `libresearch:debug_table`, `libresearch:inkwell`,
датапак-карты и дисциплины), — **заглушки для тестов**. Их задача — дать возможность
крутить механику, а не быть играбельным контентом.

Следствия:

- **Крафты не нужны.** Ни стол, ни чернильница не крафтятся (и, вероятно, не будут —
  крафт появится у того, кто делает контент-мод поверх библиотеки).
- **Отдельная вкладка креатива не нужна.** Максимум — предметы должны находиться поиском
  в креативе и быть видимыми в JEI (это работает автоматически для зарегистрированных
  предметов; отдельная вкладка только мешает).
- **Лут-таблицы для блоков** оставляем (нужны для тестов и для тех, кто строит контент),
  но приоритета не имеют.
- Ценность библиотеки = **data-driven JSON + KubeJS-биндинги + Java API**. Именно это
  надо доводить до состояния «чужой мод/скрипт может добавить своё, не трогая наш код».

## 2. Требования заказчика от 01.11.2026

Формулировки близко к оригиналу, чтобы не потерять смысл:

1. **Крафты и вкладка не нужны** — «мы библиотеку делаем, так что текущие столы и
   чернильница — заглушки для тестов. Крафты им не нужны, в целом им даже вкладка не нужна,
   максимум в конце вкладки поиска и JEI чтобы были».
2. **lang нужен** — все тексты (экран, предметы, тултипы, причины отказа) в `ru_ru`/`en_us`,
   без захардкоженных строк в коде.
3. **KubeJS-биндинги — обязательно** («kjs биндинги — необходимо!»), не «когда-нибудь».
4. **Скриптуемые карты**: и требования, и результаты карты должны уметь запускать
   произвольную логику:
   - одну или несколько **команд Minecraft**;
   - **KubeJS-события**;
   - **JS-код** (через KubeJS);
   - **Java-код** (через наш API, регистрация фабрик).
5. **Иконки дисциплин** — добавить и вывести в GUI (слева или справа, но **не конфликтовать
   с JEI**; JEI занимает правую сторону — значит, дисциплины слева, вне основной панели).
6. **Баги пофиксить** — актуальный список в `notes/11-known-issues.md`.
7. **Мультиплеер проверить** — заказчик не знает, как; вариант с двумя инстансами (ник `Dev`
   занят) описан в `notes/11` §4.
8. **`/reload` проверить** — что происходит с открытой теорией, если карту/бонус/дисциплину
   изменили или удалили.
9. **Регулировка стартового вдохновения** — через **атрибут** (как `generic.max_health`,
   `generic.movement_speed`), чтобы его меняли предметы, эффекты, `/attribute`
   (+ и −, × и ÷). Дизайн — `notes/10-starting-inspiration-attribute.md`.
10. **Бонусные блоки**: заказчик не замечал, что бонусные карты вообще выпадают — надо
    проверить в живой игре (не только в автотесте, где видно «в колоде 3 карты»).
11. **Заметки держать актуальными** — включая баги и прочую важную информацию.

## 3. Что это меняет в уже принятых решениях

| Было (notes/03, AGENTS §1–10) | Стало |
|---|---|
| Крафт чернильницы и стола — часть итерации 5 | Отменено. Рецептов не делаем |
| Вкладка креатива `LibResearch` | Удалить (предметы остаются в поиске креатива и в JEI) |

| Итерация 4 = бонусные блоки | Бонусные блоки уже реализованы; итерация 4 = проверка в игре + багфиксы |

## 4. Пересмотренный план итераций

Порядок изменён: сначала то, что делает мод **библиотекой** (расширяемость и скрипты),
потом косметика.

| № | Тема | Итог |
|---|---|---|
| 4 | Багфиксы + lang + иконки дисциплин в GUI (слева, вне зоны JEI) + убрать вкладку креатива | всё, что видно в игре, читается и переводится; вкладки нет |
| 5 | Скриптуемые карты: требования/эффекты `command`, `kubejs`, Java-фабрики в API | карта из JSON запускает команду и JS-обработчик |
| 6 | KubeJS-биндинги: регистрация карт/дисциплин/бонусов/столов из скриптов + события | карта добавляется `.js`-файлом без датапака |
| 7 | Атрибут стартового вдохновения + интеграция с формулой и GUI | `/attribute` меняет старт теории |
| 8 | Ассеты (ImageMagick) и полный lang | нет фиолетовых квадратов |
| 9 | Мультиплеер, `/reload`, перезаход, edge-cases, баланс | чек-лист QA закрыт |

Итерация 8 (ассеты) может быть разбита: иконки дисциплин нужны уже в итерации 4, поэтому
для них делаем черновые текстуры/vanilla-иконки сразу.

## 5. Критерий «библиотечности»

Мод считается библиотекой, когда выполнено:

- [ ] Новая дисциплина, карта, бонусный блок, тип стола и чернильница добавляются **только
      JSON-файлом** в датапак, без пересборки мода (`/libresearch validate` подтверждает).
- [ ] То же самое можно сделать **KubeJS-скриптом** (`ServerEvents.recipes`-подобный стиль).
- [ ] Карта может потребовать/сделать что угодно через команду или JS-колбэк.
- [ ] Есть примеры: `examples/datapack/` и `examples/kubejs/` в репозитории.
- [ ] Публичный Java API (`com.minemaster.libresearch.api`) задокументирован в `notes/`.
