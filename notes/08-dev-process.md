# Как идёт работа (процесс)

Короткая памятка: как устроен цикл разработки, чем проверяется каждая стадия и как
обрабатываются баги. Полезна и заказчику (понятно, чего ждать), и следующей сессии агента.

## 1. Ритм: одна итерация за сессию

План итераций лежит в `AGENTS.md`, критерии готовности — `notes/03-mvp-design.md` §11.

Цикл:

1. Прочитать `AGENTS.md`, `notes/README.md`, `notes/03-mvp-design.md`, последнюю заметку
   в `notes/iter/`.
2. Взять **ровно одну** итерацию, не расширяя скоуп.
3п. Сделать код.
4. Проверить (лестница проверок ниже).
5. Записать `notes/iter/NN-кратко.md` + обновить «Статус» в `AGENTS.md`.
6. Добавить изменения в git-индекс. Коммит делает заказчик
   (`iter NN: краткое описание`).

Всё, что не влезло, не выбрасывается: идёт в `notes/05-open-questions.md` или в раздел
«идеи на потом» заметки итерации.

## 2. Лестница проверок

Чем выше ступень, тем дороже и тем ближе к реальной игре. Код считается готовым,
когда пройдены все доступные ступени.

| № | Ступень | Как | Что ловит |
|---|---|---|---|
| 1 | Сборка | `./gradlew --offline build` | ошибки компиляции, ресурсы |
| 2 | Юнит-тесты | `./gradlew --offline test` | математика в `core/` (без Minecraft) |
| 3 | Сквозной сценарий на сервере | `/libresearch selftest` на dev-сервере | старт/добор/розыгрыш/завершение/награды |
| 4 | Валидация датапака | `/libresearch validate` | битые ссылки карт/бонусов/дисциплин |
| 5 | Метаданные клиента | запуск `runClient`, лог на `missing model`/исключения | регистрации, модели, экраны |
| 6 | Интерфейс глазами | скриншоты `UiTest` или проверка руками | вёрстка, хитбоксы, тултипы |
| 7 | Игра руками | заказчик | ощущения, баланс, «непонятно что делать» |

Оффлайн-сборка и тесты работают без сети. `runClient`/`runServer` требуют прогрева
через Tor-прокси (`notes/04-tech-environment.md` §5–6).

## 3. Как проверяется GUI

GUI нельзя проверить юнит-тестом, поэтому есть два пути.

**Автоматический (`client/UiTest`)** — включается только флагом:

```bash
./gradlew --offline runClient -Puitest -PclientArgs="--quickPlaySingleplayer test"
```

Он ставит стол с расходниками, прокликивает фазы, снимает скриншоты в
`run/screenshots/uitest-*.png` и закрывает игру. В обычном запуске этот код спит.

**Ручной** — `runClient`, затем `/libresearch prepare` (стол с бумагой и полной
чернильницей + открытое меню) либо обычная установка блока.

Правило: **ни один экран не считается готовым, пока не снят скриншот всех трёх фаз** —
настройка, игра, награды.

## 4. Разбор баг-репортов

Заказчик присылает список «что не работает» человеческим языком. Порядок разбора:

1. **Классифицировать**: данные / логика сервера / синхронизация / ввод / рендер.
2. Найти минимальную воспроизводимую причину, а не симптом.
3. Починить так, чтобы **решение принимал сервер**, а клиент только показывал и отправлял
   намерение. Клиентские проверки — только для подсветки кнопок, не для блокировки клика.
4. Записать баг в заметку итерации: «симптом → причина → фикс».
5. Перепроверить соседние места: если сломан один хитбокс, скорее всего сломаны все.

Типичные корни в этом проекте (уже случались):

- рендер в абсолютных координатах вместо локальных (`renderBg` до сдвига позы);
- чтение состояния из клиентского BlockEntity вместо слотов меню;
- клиентская проверка «можно ли» вместо ответа сервера;
- рассинхрон после действия: сервер забыл `markUpdated()`.

## 5. Роли

- **Заказчик** — решения по дизайну и балансу, приёмка «руками», коммиты, remote.
- **Агент** — код, данные, заметки, прогоны проверок, отладка по скриншотам и логам.

Правило чистой комнаты (`AGENTS.md`): `sources/` не читается агентом; разбор чужой
механики — только через субагента и только прозой. Журнал — `notes/06-cleanroom-log.md`.

## 6. Где что лежит

| Путь | Что |
|---|---|
| `notes/iter/NN-*.md` | журнал итерации: цель, решения, баги, как проверить |
| `notes/03-mvp-design.md` | дизайн: схема данных, экраны, критерии |
| `src/main/java/.../core/` | чистая логика без Minecraft (тесты обязательны) |
| `src/main/java/.../theory/` | движок поверх Minecraft: добор, розыгрыш, награды |
| `src/main/java/.../content/` | Codec-описания и загрузчики датапака |
| `src/main/resources/data/libresearch/libresearch/` | контент: дисциплины, карты, бонусы |
| `tools/assets/` | генерация черновых текстур (ImageMagick) |
