## 2. Долги по коду (не баги, но мешают)

- `notes/05` вопрос 11 (сгорание бонусной карты) — см. B16.
- `fullValueSlots` в MVP = число дисциплин (штраф 2/3 выключен) — осознанно.
- `spiky`/`hidden` в формуле вдохновения не подключены (нет системы исследований).

- Нет примеров для потребителей библиотеки (`examples/datapack`, `examples/kubejs`).

## 3. Как воспроизводить и проверять

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
./gradlew --offline build            # сборка
./gradlew --offline test             # юнит-тесты ядра
./gradlew --offline runServer        # затем в консоли: /libresearch selftest, /libresearch validate
./gradlew --offline runClient        # в игре: /libresearch prepare
```

Логи для разбора кликов: клиент — `UI send {ACTION}`, сервер — `UI action ... -> OK/ОТКАЗ`.

## 4. План проверки мультиплеера

Два клиента к одному серверу (ник `Dev` в инстансе не мешает, если у второго другой ник):

1. Поднять выделенный сервер: `./gradlew --offline runServer` (порт по умолчанию 25565,
   `run/server.properties`: `online-mode=false` для дев-запуска).
2. Клиент №1 — инстанс PrismLauncher `dev` (ник `Dev`), подключиться к `localhost`.
3. Клиент №2 — dev-клиент из Gradle с другим ником:
   `./gradlew --offline runClient -PclientArgs="--username Dev2 --quickPlayMultiplayer localhost:25565"`
4. Проверить:
   - [ ] оба видят один и тот же стол и одинаковое состояние теории (вдохновение, рука, прогресс);
   - [ ] добор одним игроком сразу виден второму;
   - [ ] одновременный клик по «Начать теорию» не создаёт две теории;
   - [ ] награды и знания — **личные** (attachment игрока), у второго их нет;
   - [ ] перезаход игрока посреди теории не теряет состояние;
   - [ ] `/reload` на сервере при двух открытых теориях.

## 5. `/reload` — что именно проверить

1. Открыть теорию, получить руку.
2. Изменить `data/libresearch/libresearch/card/study.json` (например, `cost: 5`), выполнить
   `/reload`.
3. Ожидание: старая карта в руке остаётся играбельной по **зафиксированным при доборе**
   значениям (rolls/targets/cost хранятся в `DrawnCard`), но новые доборы используют новые данные.
4. Удалить файл карты и `/reload` → розыгрыш карты из руки: понятный отказ, без краша.
5. Удалить дисциплину из `table_type` → прогресс по ней не должен ломать завершение теории.
6. `/libresearch validate` после каждого шага.
