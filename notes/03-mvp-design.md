# MVP: наш дизайн

> Это проектное решение, а не пересказ. Ссылки на механику оригинала — в
> `01-research-core-loop.md` и `02-research-cards-and-bonuses.md`.

## 1. Что делаем (пересказ задачи своими словами)

Библиотечный мод для NeoForge 1.21.1: «стол исследований», который играет в карточную
мини-игру и выдаёт награду. Стол — абстрактный движок, максимально data-driven; конкретный
контент (дисциплины, карты, бонусные блоки) описывается JSON-ом в датапаке, а позже — из
KubeJS.

MVP-контент:
- дисциплины: медь, железо, золото, алмаз, незерит — «обычные» ветки, и «запретная»
  (звезда Незера). Запретная — **не отдельная механика**, а просто ещё одна дисциплина.
  Никакого отдельного кода: та же схема, те же правила.
- **дисциплина невидима, пока у игрока нет по ней очков.** Как только очки появились
  (после завершения теории), дисциплина становится видимой навсегда. Видимость — чисто
  отображение: карты скрытой дисциплины всё равно могут выпасть, и именно так игрок
  «открывает» новое направление.
- источник очков — проценты за карты; 100% = 1 очко; очки копятся в «запас» игрока.
- награда **забирается вручную после завершения теории**: у дисциплины с целыми очками
  появляется ячейка с предметом (медный слиток, железный, золотой, алмаз, незеритовый
  слиток, звезда Незера), клик забирает предмет. Пока есть незабранные награды, новую
  теорию начать нельзя — висит баннер «заберите награды для продолжения».
- карты: архетипы из оригинала (прибавка прогресса, уравнивание, пересмотр, отказ,
  возврат вдохновения, бонусный добор, порог полного зачёта, выдача предмета) + требования
  (предметы с флагом «тратится», опыт, бумага/чернила, состояние теории).
- вспомогательные блоки: верстак, печь, плавильня, стол кузнеца, стол зачарований. Каждый
  даёт свой набор карт за 1 вдохновение.

Явно **вне MVP**: сканирование/наблюдения, порча/варп, небесные заметки, курьёзы,
исследования-замки (unlock через advancement — заглушка), KubeJS-биндинги, красивые ассеты.

## 2. Ключевые проектные решения

| Решение | Почему |
|---|---|
| Состояние теории — в BlockEntity, а не на игроке | несколько столов, дешёвый мультиплеер, переживает перезаход |
| Дисциплина видна только после первого очка | не засоряем GUI пустыми полосами, «открытие» направления ощущается как находка |
| Награда выдаётся не автоматически, а ячейкой «забери» | игрок видит, что именно получил; остаток процентов не теряется |
| Пока награды не забраны, новая теория не стартует | нельзя «прокрутить» награды и забыть про них, состояние стола предсказуемо |
| Очки знаний — в player attachment, в «санти-очках» (100 = 1 очко) | 110% → 1 очко + 10% остатка, как в примере заказчика; без дробей с плавающей точкой |
| Ядро расчётов — чистые Java-классы без Minecraft-типов | юнит-тесты без запуска игры, переносимость |
| Всё контентное — Codec-based JSON в датапаке | data-driven, KubeJS сможет писать JSON через DataPack-события |
| Карта = шаблон + «инстанс» с зафиксированными рандомами | подсказка не меняется между кадрами, сервер и клиент видят одно и то же |
| Требования и эффекты — полиморфные списки (`requirements[]`, `effects[]`) | новые типы добавляются модами без правки ядра |
| Ошибки игрока объясняются в GUI | в оригинале клик молча не работал |
| Штраф 2/3 и токены полного зачёта видны в интерфейсе | главный балансный рычаг не должен быть скрытым |
| Бонусные блоки ищутся с проверкой видимости | без невидимых «полок за стеной» |

## 3. Схема данных

Пути датапака:
- `data/<ns>/libresearch/discipline/<id>.json` — дисциплина (внутри `table_type`, см. итерацию 0/1)
- `data/<ns>/libresearch/card/<id>.json`
- `data/<ns>/libresearch/table_bonus/<id>.json` — бонусный блок, **глобальный реестр**
- `data/<ns>/libresearch/table_type/<id>.json` — тип стола; `bonus_blocks` — список id-ссылок
  на `table_bonus`, а не встроенные объекты (один бонус переиспользуется разными столами)
- `data/<ns>/libresearch/inkwell/<id>.json` — чернильница (предмет, ёмкость, цвет, расход)

`display` во всех определениях — пока обычная строка (ключ локализации или сырое имя);
в итерации 6 заменим на объект с описанием и иконкой.

### Дисциплина

```json
{
  "display": {
    "name": "Copper",
    "color": 14761215,
    "icon": {"item": "minecraft:copper_ingot"}
  },
  "payout": {"item": "minecraft:copper_ingot", "count_per_point": 1},
  "order": 0,
  "hidden_until_known": true,
  "unlock": {"type": "always"}
}
```

- `hidden_until_known` (по умолчанию `true`) — дисциплина не показывается, пока у игрока нет
  по ней очков. У всех шести дисциплин MVP стоит `true`, включая «запретную»: она ничем не
  отличается, просто игрок узнает о ней только когда случайно наберёт туда прогресс.
- `unlock` — задел на будущее (`always` | `advancement` | `item_in_inventory`); в MVP
  всегда `always` и ни на что не влияет. Наличие карт от видимости **не зависит**.
- `payout` — что выдаётся за 1 очко. `count_per_point` — сколько предметов за очко.
- `order` — сортировка в GUI.

### Карта

```json
{
  "cost": 1,
  "weight": 1,
  "discipline": "libresearch:copper",
  "bonus_only": false,
  "spawn": {"requirements": []},
  "requires": [
    {"type": "item", "item": "minecraft:copper_ingot", "count": 2, "consume": true}
  ],
  "effects": [
    {"type": "progress", "target": "self", "amount": {"min": 15, "max": 25}},
    {"type": "bonus_draws", "amount": 1}
  ]
}
```

- `discipline`: `null` — универсальная карта; `self` — дисциплина карты; `random` — выбирается
  при создании инстанса.
- `spawn.requirements` — условия **появления** карты (не путать с `requires`, которые
  проверяются при розыгрыше). В MVP: `progress_at_least`, `total_progress_at_least`,
  `discipline_open`, `never` (для отладки).
- `weight` по умолчанию 1; при 0 карта не выпадает. В оригинале весов нет, но они дают
  бесплатный рычаг баланса.

### Бонусный блок

```json
{
  "match": {"blocks": ["minecraft:crafting_table"]},
  "cost": 1,
  "cards": [
    {"card": "libresearch:calibration", "count": 1},
    {"card": "libresearch:tinker", "count": 2}
  ]
}
```

`match.blocks` — список id или тег; позже `match.entities`. Один тип = одна запись, дубликаты
блоков не стакаются. `count` создаёт отдельные записи колоды.

## 4. Типы требований (MVP)

| type | Поля | Поведение |
|---|---|---|
| `item` | `item`/`tag`, `count`, `consume`, `visible`, `components` | проверка инвентаря игрока (хотбар + рюкзак), списание при `consume` |
| `any_item` | `tag`/`predicate` | «любой предмет из набора», списание по флагу |
| `xp_levels` | `min`, `consume` | уровень и/или списание |
| `table_resources` | `paper`, `ink_charges` | доп. расход бумаги и зарядов чернильницы |
| `progress` | `discipline`, `min_percent` или `total_min` | состояние теории |
| `hand` | `tag` | комбо внутри руки (задел под «небесные заметки») |
| `never` | — | карта не выпадает (мёртвый контент, отладка) |

Требования — «мягкие»: если не выполнены, карту **можно** предложить, но нельзя разыграть,
и GUI объясняет причину. Отдельный флаг `hard_spawn_check` (по умолчанию true) переносит
невыполнимые требования в фильтр появления — так ведёт себя оригинал, и так
предсказуемее.

## 5. Типы эффектов (MVP)

| type | Поля | Поведение |
|---|---|---|
| `progress` | `target`, `amount` | `target`: `self`, `random`, `highest`, `lowest`, `all_equalize`, `drain`, конкретный id |
| `progress_drain` | `from`, `amount`, `spread` | снятие/перераспределение |
| `inspiration` | `amount` | возврат (обрезается стартом) |
| `bonus_draws` | `amount` | жетоны на руки из 3 карт |
| `full_value_slots` | `amount` | +1 дисциплина с полным зачётом |
| `block_discipline` | `target` | блокировка до конца теории |
| `give_item` | `item`, `count`/`range` | выдача игроку (в инвентарь, остаток на землю) |
| `consume_xp` | `levels`/`all` | списание опыта |
| `paper`/`ink_charges` | `amount` | доп. расход ресурсов стола |

Все случайные значения (`amount` диапазоном, `random` цель, случайный предмет) фиксируются
при создании инстанса карты, а не при розыгрыше.

## 6. Ядро и математика

Чистое ядро (`TheoryEngine`, `CardPool`, `KnowledgeMath`) не знает про Minecraft:

```
inspiration = min(cap, round(base + 0.5*spike + 0.1*hidden) - chosenBonusCount)
```

Конвертация при завершении:
1. сортировка дисциплин по убыванию процентов;
2. `centi = round(percent * 100 / 100)` (проценты уже целые → `centi = percent`);
3. для ранга `> fullValueSlots` → `centi = max(1, floor(centi * 2 / 3))`;
4. `knowledge[discipline] += centi`.

Штраф 2/3 реализуется, но **в MVP по умолчанию выключен** (`fullValueSlots` = число
дисциплин): иначе пример заказчика «110% общих + 80% алхимии → 1 + 1 очко» не выполняется,
потому что алхимия с рангом 1 ушла бы под штраф и дала 0. Механика и карты «+1 порог»
остаются в коде и включаются конфигом/картами, когда появится баланс.

Знания хранятся как `long` в санти-очках: 100 = 1 очко.

**Выдача награды (правка заказчика).** При завершении теории проценты сразу превращаются в
санти-очки запаса, а в столе появляется снимок наград:

```
granted[disc]   = санти-очки, начисленные этой теорией (снимок в BlockEntity)
claimable[disc] = min(granted[disc], stock[disc]) / 100      (целых очков)
pending[disc]   = item(payout.item, claimable[disc] * count_per_point)
```

- В GUI у каждой дисциплины с `claimable > 0` рисуется предмет (стек с количеством) —
  отдельная текстура ячейки не нужна, достаточно рамки/подсветки.
- Клик по предмету: награда уходит в инвентарь (если не влезает — выпадает на землю у стола),
  `stock[disc] -= claimable * 100`, `granted[disc] -= claimable * 100`. Остаток (например
  15 санти-очков из 115) остаётся и в запасе, и в снимке — следующая теория его докопит.
- Забрать нельзя больше, чем начислено этим столом, и больше, чем реально лежит в запасе:
  так два стола не могут выдать одни и те же очки дважды.
- Пока `claimable` хотя бы у одной дисциплины больше нуля, старт новой теории на этом столе
  заблокирован, в GUI висит баннер «Заберите награды для продолжения». Остаток меньше
  целого очка (15 санти) старт не блокирует.
- Если целых очков нет вовсе — старт разрешён сразу.
- Награды привязаны к столу (снимок в BlockEntity) и переживают перезаход, но не слом блока.
- Очки игрока — attachment `libresearch:knowledge` (общий для всех столов, переживает смерть).

Параметры (серверный конфиг): база 5, потолок 15, размер руки 2, шанс бонусной карты 0.25,
штраф 2/3, радиус сканирования 4/1, максимум попыток добора 10000, `start - 1` как лимит
бонусов, ёмкость чернильницы 100.

## 7. GUI (примитивно, итерация 3)

Один экран, три фазы.

**Фаза настройки**: список обнаруженных бонусных блоков с чекбоксами, ряд «лампочек»
стартового вдохновения, которое уменьшается при выборе, кнопка «Начать теорию».
Слева два слота: чернильница и бумага.

**Фаза игры**:
- сверху ряд лампочек вдохновения;
- слева стопка бумаги (клик = добор) и счётчик листов, рядом — чернильница с полоской
  зарядов;
- в центре 2–3 карты, рамка золотая у бонусных; под картой — цена, требования (иконки
  предметов с меткой «тратится»), эффект текстом;
- справа полосы дисциплин: процент, маркер блокировки, индикатор «полный зачёт / 2/3»;
  **показываются только дисциплины, у которых уже есть очки или прогресс в текущей теории**;
- снизу: жетоны бонусного добора, кнопки «Завершить» и «Сжечь теорию»;
- тултипы на всём; недоступная карта приглушена с причиной.

**Фаза наград** (сразу после «Завершить»): те же полосы дисциплин, но вместо процентов —
ячейка с предметом-наградой и количеством; курсор/тултип «Забрать». Сверху баннер
«Заберите награды для продолжения». Клик по предмету забирает всю пачку очков этой
дисциплины. Пока есть хоть одна незабранная награда, кнопка старта новой теории неактивна.
Забранные дисциплины остаются видимыми (у них появились очки).

Рендер — ванильные `GuiGraphics` + `ItemRenderer`, без собственного шейдера. Фон и рамки —
PNG, сгенерированные ImageMagick и доработанные руками.

## 8. Регистрация и синхронизация

- `DeferredRegister` для блока, чернильницы, BlockEntity, меню, attachment,
  кастомных реестров дисциплин/карт/бонусов.
- BlockEntity синхронизирует полное состояние через update-tag при каждом изменении
  (MVP-простота), счётчики — через `ContainerData`.
- Пакеты: `StartTheory`, `DrawHand`, `PlayCard(index)`, `FinishTheory`, `DiscardTheory`,
  `ClaimReward(discipline)`. Все проверяют состояние на сервере и дистанцию до блока.
- **Чернильница** `libresearch:inkwell` — предмет с прочностью (ёмкость) 100. Каждый
  розыгрыш карты тратит 1 заряд, отдельные карты — больше. Заряд = единица урона предмета.
  - крафт: стеклянная бутылочка + чёрный краситель + перо;
  - перезарядка: чернильница (любой износ) + чёрный краситель на верстаке → полная
    чернильница. Обычный shapeless-рецепт: ингредиент «чернильница» матчится независимо от
    износа, на выходе новый предмет без урона.
  - при 100 зарядов (полный износ) карты не разыгрываются, но предмет не исчезает.

## 9. Публичный API для модов и KubeJS

- Java: регистрация `CardRequirementType`, `CardEffectType`, `DisciplineUnlockType`;
  событие `RegisterResearchContent`; хелперы `ResearchApi.addCard(...)`,
  `ResearchApi.getKnowledge(player, discipline)`.
- JSON: всё вышеперечисленное; мод-контент просто кладёт файлы в свой датапак.
- KubeJS (итерация 7): `ServerEvents.highPriorityData` для генерации JSON + тонкий
  KubeJS-плагин с билдерами `ResearchCardBuilder` / `ResearchDisciplineBuilder`, события
  `ResearchEvents.theoryFinished`. Отдельный мод-компаньон не нужен, KubeJS — `compileOnly`.

## 10. Ассеты (ImageMagick)

Скрипты в `tools/assets/*.sh`, вывод в `src/main/resources/assets/libresearch/textures/`.
Генерируем: текстуру блока (16×16, дерево + бумага), GUI-панель (256×256), рамку карты
обычной/бонусной, иконки дисциплин-заглушки, «лампочку» вдохновения в двух состояниях.
Палитра — тёмное дерево, латунь, чернила. Всё помечается как «черновик, требует дорисовки».

## 11. Итерации

| № | Цель | Критерий готовности |
|---|---|---|
| 0 | Скелет сборки: Gradle + MDG, мод грузится, блок и чернильница зарегистрированы | `runClient` запускается, блок ставится, предмет крафтится |
| 1 | Реестры и данные: дисциплины/карты/бонусы, Codec-парсинг, `/reload`, команда валидации | битый JSON даёт понятную ошибку, `/libresearch validate` зелёный |
| 2 | Логика стола: слоты, бумага/заряды чернильницы, теория, добор, розыгрыш, завершение, знания, награды-ячейки; без GUI (команды) | сценарий «110% + 5% → 1 очко + 15% остатка» и блокировка старта до забора награды воспроизводятся тестом/командой |
| 3 | GUI: настройка бонусов, игровой экран, фаза наград, тултипы, причины отказа | играбельно мышью, без знания команд |
| 4 | Бонусные блоки: скан с видимостью, выбор, стоимость, отдельная конечная колода | верстак/печь/плавильня/кузнец/зачарование дают свои карты |
| 5 | Контент MVP: 6 дисциплин, 20+ карт, 5 бонусных блоков, рецепты чернильницы, лут | полная теория проходится, награда забирается предметом |
| 6 | Ассеты ImageMagick + lang + звуки-заглушки | нет фиолетовых квадратов, всё подписано |
| 7 | KubeJS + документация + пример скрипта | скрипт добавляет карту и дисциплину без Java |
| 8 | Баланс и QA: мультиплеер, перезаход, сломанный стол, лимиты, edge-cases | чек-лист `iter/08` закрыт |

Одна итерация = один файл `notes/iter/NN-*.md` + один коммит (или несколько мелких).

## 12. Не делаем в MVP (но оставляем место)

- наблюдения и сканирование предметов;
- порча/варп и её лечение;
- исследования-замки и дерево прогресса (только заглушка `unlock`);
- мультиблоки (инфузионная матрица);
- сущности-бонусы (порталы);
- несколько столов на блок (мультиблочный стол);
- собственные звуки и анимации;
- рецепты крафта стола (чернильница крафтится в итерации 5, стол — пока creative tab).
